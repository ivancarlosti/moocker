# PHP 8.5 Upgrade — Moocker

- **Date:** 2026-10-23
- **Scope:** move the Moocker image from PHP 8.3 to PHP 8.5 and align the
  Moodle core with the PHP 8.5 target branch.
- **Status:** Implemented and validated in this change set.
- **Method:** upstream release notes, Moodle PHP support policy, the
  `docker-library/php` build files, and a full local Docker build + install +
  HTTP smoke test (all retrieved on 2026-10-23).

---

## 1. Decision

Upgrade the base image to **PHP 8.5** and bump Moodle to **v5.3.0**.

Moodle 5.2 is being capped at PHP 8.4. PHP 8.5 is the target for **Moodle 5.3
and later** (MDL-84684), so 8.5 and 5.2 must not be combined. Moodle still
labels PHP 8.5 support as *in progress* for 5.3; the image is therefore shipped
with an explicit upstream-support caveat in the README and an easy
`PHP_VERSION` build-arg rollback.

## 2. Upstream support matrix (retrieved 2026-10-23)

| Source | Finding |

| Moodle 5.3 release notes (2026-10-05) | Minimum PHP 8.3.0; PHP 8.4.x supported. |
| [Moodle PHP versions policy](https://moodledev.io/general/development/policies/php) | PHP 8.5 support is *currently being implemented for Moodle 5.3 and later*, incomplete and development-only. |
| [MDL-84684](https://moodle.atlassian.net/browse/MDL-84684) | Epic "Prepare Moodle for PHP 8.5". Target agreement: PHP 8.5 with **Moodle 5.3 and up only**; branches 4.5, 5.0, 5.1 and 5.2 are to be capped at PHP 8.4 (MDL-89653). |
| `docker-library/php` | `php:8.5-apache` exists, is published for `amd64`/`arm64` (plus more), and is based on Debian 13 "trixie". |
| Moodle 5.3 server requirements | MariaDB minimum raised to **11.4.0** (was 10.11.0 in 5.2). |

Relevant PHP 8.5 changes reviewed against Moodle's usage:

- non-canonical cast names (`(boolean)`, `(integer)`, `(double)`, `(binary)`)
  are deprecated — Moodle's remaining occurrences only emit `E_DEPRECATED`;
- `__sleep()`/`__wakeup()` are soft-deprecated — deprecation notices only;
- semicolons after `case` statements, backtick shell execution, and `null`
  array offsets are deprecated — fixed in Moodle 5.3 (MDL-89052, MDL-88899,
  MDL-88702);
- `array_key_exists(null, ...)` and `setlocale(0, ...)` deprecations remain open
  upstream (MDL-90014, MDL-89723) and are non-fatal.

Moodle's bootstrap only enforces a **minimum** PHP version (`public/lib/setup.php`
requires PHP >= 8.1 for the bootstrap, `public/admin/environment.xml` requires
>= 8.3.0 for Moodle 5.3). There is no hard maximum, so PHP 8.5 boots; the
remaining gaps surface as deprecation notices, not fatal errors.

## 3. Changes

### `Dockerfile`

```dockerfile
# PHP version used for the base image. Override at build time when needed:
#   docker build --build-arg PHP_VERSION=8.4 -t moocker .
ARG PHP_VERSION=8.5
FROM php:${PHP_VERSION}-apache
```

- `ARG MOODLE_VERSION` bumped from `v5.2.3` to `v5.3.0`.
- Removed `opcache.fast_shutdown=1`; the directive was removed from PHP in 8.0
  and is dead configuration.
- OPcache is compiled into the current PHP 8.4 and 8.5 base images, so the
  Dockerfile only runs `docker-php-ext-install opcache` when `php -m` does not
  already report `Zend OPcache` (covering base images where it is a shared
  extension).
- Added an Apache `FallbackResource /r.php` for the `public/` docroot. Moodle 5.x
  serves its ESM/React assets through `public/r.php`; without the fallback,
  `/core/esm/...` returns 404 and JavaScript blocks (starting with the course
  overview) never finish loading.
- Extension set, OPcache tuning and PHP limits are otherwise unchanged:
  `mysqli zip gd intl soap exif` (plus the built-in OPcache),
  `memory_limit=512M`, `max_execution_time=300`, `post_max_size=50M`,
  `upload_max_filesize=50M`, `max_input_vars=5000`.

### Documentation

- `README.md`: PHP 8.5 / Moodle v5.3.0 references, MariaDB 11.4+ prerequisite,
  upstream-support note, `PHP_VERSION` build-arg fallback.

## 5. Results

The image builds and the full Moodle lifecycle works on PHP 8.5.12 with
Moodle 5.3 (2026100500):

- **Install:** a fresh install against MariaDB 11.4.13 completed with
  `Installation completed successfully.` and no fatal errors.
- **Upgrade:** `upgrade.php` reports no pending upgrade.
- **Cron:** `cron.php` completes correctly and the container's cron daemon
  keeps running scheduled tasks.
- **Web:** login works end-to-end, the dashboard, course, course management and
  site administration pages render, and Playwright can capture them.
- **Deprecations observed (non-fatal):** the backtick operator
  (`moodlelib.php:9040`), `xml_parser_free()` (`xml_parser.php:190`), null array
  offsets (`mysqli_native_moodle_database.php:1371/1375`,
  `plugin_manager.php:674`) and a null `array_key_exists()` key
  (`special_gradeexportdefault.php:48`). These match the upstream PHP 8.5 work
  tracked in MDL-84684 and do not block install or normal use.
- **Router fix required:** before adding `FallbackResource /r.php`, Moodle 5.3's
  `/core/esm/...` assets returned 404 and the dashboard stayed on skeleton
  placeholders. The fix is part of this change set.

No fallback to PHP 8.4 was needed.

## 6. Rollback

- Rebuild with the last fully supported runtime:
  `docker build --build-arg PHP_VERSION=8.4 -t moocker:local .`
- Revert `ARG MOODLE_VERSION` to `v5.2.3` only if the Moodle bump itself has to
  be reverted; do not run Moodle 5.2 on PHP 8.5 (upstream caps it at 8.4).
